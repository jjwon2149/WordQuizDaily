# 다음 배포 학습 연속성과 신뢰성 개선 계획

작성일: 2026-09-30. 상태: 로컬 구현 및 핵심 검증 완료, 배포 검증 미완료. 이 문서는 다음 배포의 구현 및 검증 계약이다. 실제 확인 결과는 [검증 기록](qa/next-release-verification.md)에 남긴다. 미확인 배포 조건은 완료 표시하지 않는다. 구현 단계의 체크는 코드 반영 및 해당 자동 검증을 뜻하며, 기기 동작은 별도 인수 조건과 검증 기록으로 판단한다.

## 목표

틀린 단어를 저장하고 다시 학습하며, 수준에 맞는 문제를 풀고 학습 결과를 확인할 수 있게 한다. 앱을 열지 않아도 위젯이 날짜에 맞는 단어를 제공하고, 알림과 자동 검증을 정비해 배포 신뢰성을 높인다.

## 요청과 현재 근거

- 기존 리뷰의 다섯 문제인 학습 기록 부재, 명사 중심의 소규모 콘텐츠와 무작위 출제, 위젯 날짜 갱신, 자동 검증 부재, 알림 로그 및 미구현 서버 코드 혼재를 이번 배포에서 다룬다.
- `QuizViewModel`은 정오답을 현재 화면 상태에만 보관하며 `randomWord(excluding: [])`로 다음 문제를 고른다.
- 기본 콘텐츠는 `LearningWordRepository.swift`에 들어 있는 40개 명사다. 보기 생성에는 난이도 조건이 없다.
- 위젯은 날짜만 있는 타임라인 항목을 만들고 화면에서 공유 저장소의 마지막 단어를 읽는다.
- 알림 예약은 당시 본문을 매일 반복한다. 서버 예약 함수는 TODO이며 토큰과 알림 payload를 출력하는 코드가 여러 파일에 있다.
- 현재 프로젝트에는 앱·위젯 타깃만 있으며 테스트 타깃과 CI 워크플로가 없다.
- 로컬 프로젝트의 앱 버전은 1.0.5, 빌드는 6이다. App Store Connect의 최신 업로드 상태는 확인하지 않았다.

## 포함 범위

- 기기 내 학습 기록, 오답 복습, 간단한 학습 현황.
- 초급·중급·고급 선택과 같은 수준의 문제 및 보기 생성.
- 검수된 60개 이상 콘텐츠와 명사·동사·형용사 지원.
- 앱·위젯의 날짜별 단어 선택 로직 공유 및 기존 공유 저장 키 호환.
- 반복 알림의 오래된 단어 문제 해결, 민감 로그 제거, 미구현 서버 흐름 정리.
- 핵심 규칙 테스트, 빌드 및 테스트 CI, 수동 QA와 배포 점검.

## 제외 범위

- 계정, 로그인, 클라우드 동기화, 서버 알림 예약, CMS, 결제 개편.
- 전체 UI 재설계, 음성 기능, 리더보드, 복잡한 간격 반복 알고리즘.
- 대규모 사전 구축, 일본어 학습 콘텐츠 전체 번역, 광고 SDK 교체.
- App Store 심사 제출. 앱 구현과 TestFlight 업로드는 이후 사용자의 명시적 요청으로 승인되어 진행했다.

## 설계 가정

- 핵심 대상은 한글을 읽을 수 있는 외국인 한국어 학습자다. 입문 문자 교육은 다루지 않는다.
- 새 사용자 기본 수준은 초급, 기존 사용자는 현재 경험을 유지하도록 전체 수준으로 이전한다. 설정에서 언제든 변경할 수 있다.
- 수준 선택은 일반 퀴즈에 적용한다. 오늘의 단어는 모든 사용자에게 같은 날짜별 단어를 제공한다. 복습은 수준 변경 전 오답도 포함하며 난이도를 표시한다.
- 학습 기록은 이 기기에만 보관한다. 삭제 후 재설치 시 복원이 보장되지 않는다는 점을 설정에 알린다.
- 60개와 아래 복습 규칙은 이번 배포를 실행 가능하게 만들기 위한 제안 기준이다. 확정된 교육 효과나 사용자 지표로 표현하지 않는다.
- 배포 버전과 일정은 업로드 이력 및 콘텐츠 검수 가능 시점 확인 후 확정한다.

## 구현 단계

### 1단계 기준 상태와 검증 기반 확보

- [x] 현재 변경 파일을 확인하고 기존 작업을 보존한다. CodeGraph 사용 가능 여부를 확인하고 변경 영향도를 조사한다. 사용할 수 없다면 검색으로 대체했음을 기록한다.
- [ ] Xcode 라이선스 미동의 문제를 소유자가 해결한 후 기존 앱·위젯 빌드를 실행하고 결과를 남긴다. 라이선스를 대신 동의하지 않는다.
- [x] workspace와 project의 `Package.resolved`를 비교해 실제 빌드 기준을 정한다. 목적 없는 의존성 업그레이드는 하지 않는다.
- [x] 테스트 실행 경로를 먼저 만든다. 권장안은 Firebase·광고 SDK·앱 실행 없이 테스트할 수 있는 Foundation 기반 로컬 Swift 패키지다. 앱과 위젯이 동일한 실제 구현을 사용하도록 연결하고 테스트용 복제 코드는 만들지 않는다.
- [x] 시계, 난수, 저장 위치를 주입할 수 있게 해 날짜와 출제 테스트를 재현 가능하게 만든다.

완료 기준: 기존 빌드 결과와 신규 테스트 실행 경로가 기록되고, 기존 기능 변경 없이 최소 테스트가 실제 실행된다.

### 2단계 민감 로그와 일일 콘텐츠 수정

- [x] 앱·알림 서비스 전체에서 FCM/APNs 토큰, raw payload, 개인 데이터 및 URL 전체를 출력하는 경로를 점검한다. 민감 값은 Debug에서도 제거하고 이벤트명·성공 여부만 남긴다.
- [x] 동작하지 않는 서버 전송·예약·취소 호출을 설정의 실제 동작 경로에서 제거한다. FCM 수신과 딥링크는 유지하고 로컬 알림을 실제 예약 수단으로 문서화한다.
- [x] 반복 로컬 알림을 단어가 포함되지 않은 현지화된 학습 안내로 바꾼다. 기존 예약 식별자를 교체 갱신해 과거 단어가 계속 전송되지 않게 한다. 언어·시간·권한·토글 변경 시 예약 상태를 동기화한다.
- [x] 앱과 위젯이 동일한 번들 데이터와 날짜 선택기를 사용하게 한다. 타임라인 항목에 해당 날짜의 단어를 담고 다음 현지 자정의 새 항목을 미리 구성한다. 시스템이 실제 표시 갱신 시각을 보장하지 않는 한계는 구분한다.
- [x] 시간대와 일광절약시간 변경에도 현지 날짜별로 결정되도록 달력 날짜를 기준으로 계산한다. 단순 초 단위 일수 계산에 의존하지 않는다.
- [x] 업데이트 당일은 유효한 기존 `TodayLearningWordID`와 날짜를 앱·위젯이 함께 존중하고, 다음 날부터 새 선택 규칙을 사용한다. 오래된 캐시는 날짜 검증 후 무시한다.
- [x] 기존 `TodayWord`와 관련 키를 유지하고 홈 갱신·설정 변경 시 위젯 reload를 요청한다. FCM payload의 공유 키 쓰기가 날짜별 단어를 덮어쓰지 않도록 조정한다.

완료 기준: 앱을 열지 않은 다음 날에도 위젯의 준비된 항목은 해당 날짜의 단어를 사용하고, 알림에 오래된 단어가 반복되지 않는다. 수신 및 탭 이동은 유지된다.

### 3단계 콘텐츠와 수준별 출제

- [x] 40개 기존 단어의 ID를 보존하면서 콘텐츠를 코드 로직에서 번들 데이터로 분리한다. 누락 데이터가 자동 제외되어 배포되는 대신 검증 실패로 드러나게 한다.
- [x] 검수된 콘텐츠를 최소 60개, 난이도별 최소 20개로 정비한다. 각 수준에는 명사·동사·형용사가 각각 최소 4개 있어 같은 수준·품사의 네 보기를 만들 수 있게 한다.
- [x] 모든 단어의 뜻·난이도·자연스러운 예문·영문 번역·로마자 표기·오답 힌트를 검수한다. 기존 단어 난이도도 재평가하고 검수 결과를 남긴다. 자동 필드 검증으로 언어 품질 검수를 대체하지 않는다.
- [x] 품사 표시를 세 언어로 확장하고 기존 난이도 문자열과 새 내부 표현의 호환을 유지한다.
- [x] 수준 선택을 저장하고 일반 퀴즈의 정답 및 보기를 같은 수준·품사에서 고른다. 같은 뜻으로 정답이 될 수 있는 보기는 제외한다. 제외 후에도 네 보기를 만들 수 있는지 전체 데이터 대상으로 검증한다.
- [x] 최근 3개 정답 단어는 일반 출제 후보에서 제외한다. 후보가 부족하면 가장 오래된 제외 항목부터 해제하되, 다른 후보가 있으면 직전 문제는 반복하지 않는다.
- [x] 필터 결과로 네 개의 유효한 보기를 만들 수 없다면 수준을 몰래 섞지 않고 복구 가능한 안내를 표시한다.
- [x] 영어 퀴즈의 질문에 영어 뜻을 사용하고, 일본어 UI의 한국어 학습 설명에는 영어 뜻을 보조로 제공한다. 일본어 단어 번역 지원으로 홍보하지 않는다.
- [x] 이미지 요청에 요청 식별자를 전달하고 이전 문제의 늦은 응답이 현재 문제 이미지를 덮어쓰지 않게 한다. 오프라인·이미지 실패에도 답변은 가능해야 한다.

완료 기준: 승인된 모든 단어에 중복·의미 모호성이 없는 네 보기를 생성할 수 있고, 선택 수준과 품사 정책을 지킨다.

### 4단계 학습 기록과 복습 연결

- [x] 단어 ID, 답변 횟수, 정답 횟수, 마지막 학습일, 복습 필요 여부, 오답 이후 연속 정답 횟수를 저장한다. 버전이 있는 Codable 파일을 원자적으로 저장하고 저장 실패를 성공으로 표시하지 않는다.
- [x] 첫 설치 및 기존 버전에는 빈 기록으로 시작하되 알림·공유 단어·기존 설정은 보존한다. 손상 파일은 격리하고 복구 안내 후 새 기록으로 진행한다. 삭제된 단어 ID는 출제에서 건너뛰고 기록은 보존한다.
- [x] 문제당 최초 제출만 한 번 기록한다. 버튼 연타나 화면 재등장으로 중복 기록하지 않는다.
- [x] 틀린 단어는 즉시 복습 대상으로 남긴다. 이후 서로 다른 두 문제에서 연속 정답이면 복습 목록에서 해제하고, 다시 틀리면 연속 정답 횟수를 0으로 돌린다.
- [x] 홈에 오늘 푼 문제 수, 복습할 단어 수, 복습 시작 버튼을 제공한다. 학습 기록이 없거나 복습할 단어가 없을 때의 안내를 구현한다.
- [x] 복습은 마지막 학습이 오래된 항목부터 최대 10개 고유 단어로 세션을 시작한다. 세션에서 한 단어를 중복 출제하지 않고 종료 시 정답 수와 남은 복습 수를 보여준다. 해제 기준이 충족되지 않은 단어는 다음 세션에 남는다.
- [x] 앱 재실행 후에도 기록과 복습 대상이 유지되고, 수준 변경으로 기존 복습 대상이 사라지지 않게 한다. 공통 저장·선택 테스트 통과, 실제 UI 왕복 시나리오는 미검증.
- [x] 사용자에게 기록이 기기에 저장됨을 설명하고 설정의 명시적 확인을 거친 학습 기록 초기화를 제공한다. 알림 설정이나 오늘의 단어 캐시는 함께 삭제하지 않는다.

완료 기준: 오답 제출 → 앱 종료·재실행 → 홈에서 복습 → 두 문제 연속 정답 → 복습 대상 해제 흐름이 실제 동작한다.

## 인수 조건

- [ ] 토큰·raw payload가 앱의 Debug/Release 로그에 나타나지 않는다.
- [ ] 앱을 하루 이상 열지 않은 위젯 시나리오에서 날짜별 항목이 올바르고, 앱을 열면 같은 단어를 표시한다.
- [ ] 알림 거부·해제·시간 변경·언어 변경·탭 이동이 정상이며 오래된 단어 알림이 없다.
- [ ] 60개 이상 검수된 콘텐츠, 수준별 20개 이상, 각 수준·품사별 네 개 이상의 기준을 충족한다.
- [ ] 각 문제의 정답은 정확히 하나이고 보기는 네 개이며 중복 및 의미상 복수 정답이 없다.
- [ ] 틀린 단어가 재실행 후 남고 복습 규칙대로 해제되며, 중복 제출은 한 번만 기록된다.
- [ ] 기록 손상·저장 실패가 앱 종료나 조용한 데이터 덮어쓰기로 이어지지 않는다.
- [ ] 핵심 Home·Quiz·복습·위젯은 네트워크 없이 동작한다.
- [ ] 한국어·영어·일본어 UI에 원시 키가 없고 작은 화면 및 큰 글자에서 주요 버튼을 사용할 수 있다.

## 검증 계획

### 자동 검증

권장 패키지 경로를 `WordQuizDaily/Packages/LearningCore`로 정한 경우 저장소 루트에서 실행한다. 경로가 바뀌면 이 문서와 CI 명령을 함께 수정한다.

```sh
swift test --package-path WordQuizDaily/Packages/LearningCore
xcodebuild -workspace WordQuizDaily/WordQuizDaily.xcworkspace -scheme WordQuizDaily -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO
xcodebuild -workspace WordQuizDaily/WordQuizDaily.xcworkspace -scheme WordQuizWidgetExtension -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO
```

테스트에는 다음 실제 동작을 포함한다.

- 같은 날 안정성, 자정·연말·윤일·시간대·일광절약시간 변화, 기존 당일 캐시 이전, 오래된 캐시 무시.
- 수준·품사 필터, 최근 문제 제외, 후보 부족, 보기 중복 및 유사 의미 제외, 전체 콘텐츠 필수 필드와 ID 검증.
- 오답 등록, 연속 정답 해제, 재오답, 중복 제출 방지, 수준 변경, 세션 종료 및 빈 목록.
- 저장 후 재로딩, 기록 버전 이전, 손상 파일, 저장 실패, 삭제된 단어 ID.
- 이전 이미지 응답 무시, 권한 거부 및 알림 해제 시 예약 취소 규칙.

UI나 알림 어댑터의 규칙을 패키지 밖에 남기는 경우 해당 부분의 XCTest 타깃을 추가하고 실제 scheme과 simulator를 지정한 `xcodebuild test` 명령을 CI에 등록한다. 단순 빌드를 테스트 통과로 보고하지 않는다.

### 수동 검증

- 신규 설치: 기본 초급 → 일반 문제 정답·오답 → 홈 현황 → 복습 → 종료 화면.
- 업데이트 설치: 기존 설정·당일 단어 유지 → 기록 초기 상태 → 다음 날 앱과 위젯 일치.
- 복습: 틀린 후 강제 종료 → 재실행 → 복습 대상 유지 → 연속 정답 두 번으로 해제 → 다시 틀리면 재등록.
- 오프라인: 설치된 번들로 앱·퀴즈·복습·위젯 사용, 이미지 실패 중 답변 가능.
- 위젯: 앱을 열지 않고 자정을 넘긴 경우, 서로 다른 시간대, 새 설치 후 첫 실행 전, 공유 캐시가 오래된 경우. 타임라인 테스트와 기기 관찰을 구분해 기록.
- 알림: 허용·거부·시스템 설정에서 권한 철회·토글 해제·시간 변경·언어 변경·수신 탭 이동. 실제 기기에서 확인.
- 화면: ko/en/ja, 작은 iPhone 화면, 큰 글자, VoiceOver의 선택지·정오답·복습 버튼 읽기.
- TestFlight: 실제 Release 구성의 실행, 광고 및 FCM 기존 연동 회귀 확인.

## 위험과 대응

- 콘텐츠 검수가 일정의 주요 변수다. 단어 수만 채워 완료하지 않으며, 검수자 또는 검수 근거가 없으면 배포 후보 확정을 보류한다.
- 공통 모델을 이동할 때 앱·위젯 타깃 등록과 번들 리소스 접근이 달라질 수 있다. 초기 단계부터 양쪽 빌드를 유지하고 위젯에 앱 전용 SDK를 연결하지 않는다.
- 기록 도입은 데이터 보존 책임을 만든다. ID 안정성·원자적 저장·실패 안내·초기화 범위를 먼저 확정하고 저장 테스트를 선행한다.
- WidgetKit 표시 갱신은 시스템 일정에 영향을 받는다. 정확한 시각 갱신을 보장한다고 홍보하지 않고 미리 생성한 날짜별 항목의 정확성을 검증한다.
- 계획 작성 당시 Xcode 라이선스 미동의 문제는 실행 단계에서 해소되었다. Xcode 27.0과 초기 Git 상태 조회는 확인했으며, 일부 후속 Git diff 명령의 지연과 실제 빌드 결과는 검증 기록에서 구분한다.
- 배포 후 기록 문제가 발견되면 기존 기록을 지우지 않는 수정 버전을 준비한다. 배포 중단 가능 여부와 절차는 실제 배포 시점의 App Store Connect에서 확인한다.

## 작업 순서와 배포 판단

1단계 → 2단계 → 3단계 → 4단계 → 5단계 순서로 작은 변경 단위로 진행한다. 콘텐츠 검수는 3단계 초기에 시작한다. 정확한 소요일은 기준 빌드와 검수 가능 여부 확인 후 산정하며, 심사 기간은 개발 일정과 분리한다.

필수 인수 조건이 하나라도 미충족이면 다섯 문제를 해결한 배포로 선언하지 않는다. 특히 기록 유실, 복수 정답, 위젯 날짜 오류, 알림 해제 실패, 핵심 오프라인 실패, 민감 로그 잔존은 배포 차단 항목이다.
